# 库存与履约健康度诊断

## 一、核心判断：总量问题还是结构问题

库存诊断的第一步不是看总量，而是看**结构**。

- **总量问题**：所有品类的可支撑天数同步偏离 → 属于采购计划整体失误
- **结构问题**：一部分品类缺货（< 7 天）同时另一部分积压（> 90 天）
  → 属于补货策略未分层，是更常见也更可修复的情况

结构问题的典型表现：
```
缺货 SKU 占比上升 + 积压品类可支撑天数上升 + 出库结构未见异常
```
「货在动，但动到了错误的品类上」——出库正常说明仓库与履约没问题，
问题在**补货决策**。

## 二、安全库存的重新计算

安全库存 = 日均销量 × 补货周期 × 安全系数

- 补货周期：从下单到入库的自然天数（含供应商生产 + 物流）
- 安全系数：A 类品 1.5、B 类品 1.2、C 类品 1.0

常见错误：所有 SKU 用同一个安全库存值。正确做法是按 **ABC 分层**：

| 分层 | 销量贡献 | 补货策略 | 安全库存上浮 |
| --- | --- | --- | --- |
| A 类 | 前 70% | 小批量高频，周期 ≤ 3 天 | +30% |
| B 类 | 70%~90% | 常规补货，周期 ≤ 7 天 | 基准 |
| C 类 | 后 10% | 按需补货，禁止大批量 | -20% |

## 三、ABC 分层的落地动作

1. 按近 30 天销量降序排列全部 SKU
2. 累计销量达到 70% 的划为 A 类，70%~90% 为 B 类，其余为 C 类
3. A 类品：安全库存上浮 30%，补货周期压缩到 3 天，缺货即告警
4. C 类品：改为小批量高频补货，单次补货量不超过 15 天销量
5. 每季度重算分层（爆品迭代会改变分层结构）

## 四、积压处置

积压的判定：可支撑天数 > 90 天，或库龄 > 90 天。

处置优先级（按资金占用排序）：
1. **高单价 + 高库龄**：优先促销清仓，哪怕让利也要回收现金
2. **低单价 + 高库龄**：捆绑销售或作为赠品消化
3. **可二次销售性差的**：尽快报废，避免继续占用仓容

## 五、监控指标

| 指标 | 告警阈值 |
| --- | --- |
| 缺货 SKU 占比 | > 5% |
| 单品类可支撑天数 | < 7 天 或 > 90 天 |
| A 类品缺货数 | > 0（立即处理） |
| 库龄超过 90 天的库存金额占比 | > 10% |

## 六、常见误判

- **把缺货当成需求暴涨**：需求没变，是补货没跟上。先看日均销量的变化，
  销量未涨而缺货扩大，一定是补货问题。
- **把积压当成采购失误**：积压往往是「曾经卖得好、现在卖不动」，
  属于动销结构变化，需要的是清库而不是追责。
- **忽略在途库存**：`in_transit_qty` 未到货但已下单的部分不应计入可售，
  但也不应重复补货。缺少预计到货时间是常见的盲区。
